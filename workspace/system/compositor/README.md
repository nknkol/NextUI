## NextUI 合成器系统：协议使用与开发指南

### 1\. 系统概述

本系统是一个基于客户端/服务器架构的图形合成器，旨在为嵌入式设备或特定用途的计算机提供一个灵活、高效的窗口和UI管理环境。

**主要组件:**

1.  **合成器 (Compositor)**: 核心服务 (`compositor.elf`)，负责管理所有客户端、合成画面并将其渲染到屏幕。
2.  **客户端库 (Client Library)**: 为应用程序提供了与合成器交互的C语言API。
3.  **协议 (Protocol)**: 定义在 `protocol.h` 中，是客户端与服务器之间通信的数据结构和规则。
4.  **应用程序 (Application)**: 使用客户端库与合成器通信的独立程序。

**核心特性:**

  * **多客户端管理**: 支持多个应用同时连接，并通过槽位（Slot）进行管理。
  * **分层与区域渲染**: 支持多达4个可自定义位置和大小的叠加层。
  * **双模（混合）应用**: 应用程序可以同时支持作为合成器客户端运行或在没有合成器时独立运行。
  * **生命周期管理**: 合成器可以暂停和恢复客户端的渲染，以节省资源。
  * **外部程序兼容**: 允许通过Linux信号暂停合成器，为不支持本协议的“遗留”程序让出屏幕。

### 2\. 双模（Hybrid）应用程序设计指南

这是一个核心设计理念，旨在让您的应用程序更具灵活性。一个“非叠加层”应用（通常是主应用）应该能够适应两种运行环境。

**设计目标**: 程序逻辑（特别是渲染逻辑）应尽可能保持一致，但在启动时检测环境，选择不同的工作模式。

**检测机制**:
应用程序在启动时，应首先尝试连接到合成器：

```c
ClientConnection* conn = client_connect(slot_hint, "My App", CLIENT_TYPE_NORMAL);

if (conn != NULL) {
    // 连接成功 -> 进入客户端模式
    run_in_client_mode(conn);
} else {
    // 连接失败 -> 进入独立模式
    run_in_standalone_mode();
}
```

#### 2.1. 客户端模式 (Client Mode)

  * **行为**: 当检测到合成器时，应用作为客户端运行。
  * **职责**:
      * 通过 `client_lib` 与合成器通信。
      * 从 `client_get_render_buffer()` 获取帧缓冲区。
      * 通过 `client_present()` 提交帧。
      * 响应 `SIGUSR1`/`SIGUSR2` 信号进行合作式暂停/恢复。
  * **优势**: 可以与其他应用（如图标、状态栏等叠加层）共存，由合成器统一管理。

#### 2.2. 独立模式 (Standalone Mode)

  * **行为**: 当没有检测到合成器时，应用独立运行。
  * **职责**:
      * **自己创建窗口**: 必须自己初始化SDL，并创建 `SDL_Window` 和 `SDL_GL_Context`。
      * **自己管理缓冲区**: 为了复用 `render_scene()` 函数（它需要一个 `uint8_t*` 指针），应用需要自己 `malloc` 一块CPU侧的内存作为帧缓冲区。
      * **自己显示画面**: 在每一帧，应用需要：
        1.  调用 `render_scene()` 在CPU侧缓冲区上绘制。
        2.  将CPU侧缓冲区的内容上传到一个OpenGL纹理 (`glTexSubImage2D`)。
        3.  绘制一个覆盖全屏的矩形，并将该纹理贴上去。
        4.  调用 `SDL_GL_SwapWindow()` 将画面显示到屏幕。
  * **优势**: 保证了程序的核心功能在没有合成器环境时依然可用。

**核心思想**: 无论在哪种模式下，应用的核心 `render_scene()` 函数都被复用。模式的切换只影响“画板”的来源（来自合成器或自己创建）和“提交”的方式（发送给合成器或自己显示）。

### 3\. 叠加层系统使用指南

本系统支持最多4个叠加层，并允许它们在屏幕的任意矩形区域内进行渲染。

#### 3.1. 渲染范式：“虚拟屏幕”与“窗口”

请务必理解这个核心概念：

  * **客户端的帧缓冲区**: 每个客户端（包括叠加层）都拥有一个与屏幕一样大（例如1024x768）的“虚拟屏幕”或“画布”。
  * **合成器的角色**: 合成器像是在这个巨大的虚拟画布上开了一个“窗口”（即您指定的区域）。它只会把这个窗口区域的内容显示在屏幕的对应位置上。

**这对客户端开发的意义**:
如果一个叠加层被指定显示在 `(x=800, y=20, w=200, h=50)` 的区域，那么这个客户端应用就应该在**自己1024x768的大画布**的 `(800, 20)` 坐标开始绘制一个 `200x50` 的UI。**坐标系是统一的。**

#### 3.2. API 使用

  * **设置叠加层**:
    ```c
    // 将当前客户端设置到 1号叠加层，显示在屏幕左上角一个250x250的区域
    client_set_overlay_region(conn, 1, 20, 20, 250, 250);
    ```
  * **清除叠加层**:
    ```c
    // 清除1号叠加层
    client_clear_overlay_index(conn, 1);
    ```

#### 3.3. 注意事项 (冲突处理)

1.  **Z轴顺序 (Z-Ordering)**: 叠加层的**索引号 (`overlay_index`)** 决定了其绘制顺序。索引号越大，层级越高（越靠近观众）。如果两个叠加层区域重叠，索引号大的会覆盖在索引号小的上面。

2.  **逻辑冲突 (Channel Conflict)**:

      * **当前机制**: 系统是“合作式”的，采用“后来者优先”原则。如果两个应用都尝试设置同一个叠加层索引，后发送命令的应用会抢占这个通道。
      * **推荐的架构**: 为了避免冲突，强烈建议采用\*\*“管理式”架构\*\*。即：
          * 创建一个唯一的“系统UI管理器”应用。
          * 只有这个管理器有权调用 `client_set_overlay_region` 和 `client_clear_overlay_index`。
          * 其他普通叠加层应用启动后只连接，不设置自己的位置，等待管理器来布局。
          * 管理器通过 `client_list_clients()` 发现新连接的叠加层服务，并根据统一的布局规则为其分配通道和区域。

### 4\. 客户端开发通用流程

1.  **包含头文件**: `#include "client_lib.h"` 和 `#include "protocol.h"`。
2.  **模式检测**: 在 `main` 函数开头尝试 `client_connect()` 判断运行模式。
3.  **进入相应模式**:
      * **客户端模式**:
          * 安装信号处理器: `client_install_signal_handlers()`。
          * 配置能力: `client_enable_render_pause()` 等。
          * 进入主循环，循环内：
              * 检查暂停状态: `if (client_is_paused()) ...`
              * 获取缓冲区: `client_get_render_buffer()`。
              * 绘制场景。
              * 提交缓冲区: `client_present()`。
          * 程序退出前断开连接: `client_disconnect()`。
      * **独立模式**:
          * 初始化SDL，创建窗口和GL上下文。
          * 创建自己的CPU帧缓冲区和用于显示的GL纹理。
          * 进入主循环，循环内：
              * 在自己的缓冲区上绘制场景。
              * 上传缓冲区到纹理。
              * 绘制全屏矩形并显示纹理。
              * 交换窗口: `SDL_GL_SwapWindow()`。
          * 程序退出前释放所有SDL和GL资源。

### 5\. 合成器 (`compositor.elf`) 启动参数

这些是在您启动合成器服务时，可以附加在命令后面的参数。

| 参数 | 示例 | 说明 |
| :--- | :--- | :--- |
| `--home-slot <ID>` | `./compositor.elf --home-slot 0` | 指定一个槽位ID作为“Home”应用。当没有活动应用时，合成器会自动切换到该槽位的应用。 |
| `--debug` | `./compositor.elf --debug` | 开启一个叠加在所有画面之上的调试HUD，显示FPS、活动客户端等信息。 |

**组合使用示例:**

```sh
# 启动合成器，指定0号槽位为Home，并开启调试界面
./compositor.elf --home-slot 0 --debug
```

-----

### 6\. 客户端应用 (`app_*.elf`) 启动参数

我们的客户端应用被设计为可以接收一个参数来指定它想向合成器请求的槽位ID。

| 参数 | 示例 | 说明 |
| :--- | :--- | :--- |
| `<slot_hint>` | `./app_C_exclusive.elf 0` | 客户端启动时向合成器请求的槽位ID。**-1** 表示请求任意可用槽位；**\>=0** 的值表示请求一个指定的“预留”槽位。 |

-----

### 7\. 运行时管理命令 (通过协议发送)

这些是通过 `client_lib` 库的函数发送给合成器的字符串命令，用于在运行时动态控制系统状态。

| 命令字符串 | 参数 | API 函数 | 说明 |
| :--- | :--- | :--- | :--- |
| `SET_FOREGROUND` | `<client_slot_id> <MODE>` | `client_set_foreground()` | 将指定槽位的客户端设为前台。<br> `MODE` 可以是 `NORMAL` 或 `EXCLUSIVE`。 |
| `SET_OVERLAY` | `<client_slot_id> <overlay_idx> <x> <y> <w> <h>` | `client_set_overlay_region()` | 将指定客户端设置到指定的叠加层通道，并定义其在屏幕上的显示区域。 |
| `CLEAR_OVERLAY`| `<overlay_idx>` | `client_clear_overlay_index()` | 清空指定的叠加层通道，使其不再显示任何内容。 |
| `HIDE_CLIENT` | `<client_slot_id>` | `client_hide()` | 暂停并隐藏一个客户端（从前台或叠加层中移除）。 |
| `TERMINATE_CLIENT`| `<client_slot_id>` | `client_terminate()` | 请求合成器向指定客户端进程发送终止信号。 |
| `LIST_CLIENTS` | (无) | `client_list_clients()` | 请求合成器返回当前所有已连接客户端的信息列表。 |

-----

### 8\. 外部程序兼容控制 (Linux 信号)

这不是一个“参数”，而是一种控制方式，用于让不支持本协议的遗留程序运行。

| 控制方式 | 命令示例 | 说明 |
| :--- | :--- | :--- |
| **暂停合成器** | `kill -STOP $(cat /tmp/compositor.pid)` | **强制暂停**合成器进程，让出屏幕。 |
| **恢复合成器** | `kill -CONT $(cat /tmp/compositor.pid)` | **恢复**之前被暂停的合成器进程。 |

-----

### 9\. 系统启动与兼容性

  * **启动脚本 `launch.sh`**: 负责以正确的参数（`--home-slot`, `--debug`）启动合成器，并为需要“预留槽位”的应用传递正确的槽位ID。
  * **兼容遗留程序**: 对于不支持本协议的程序，可以通过向合成器进程发送 `SIGSTOP` (暂停) 和 `SIGCONT` (继续) 信号来临时让出屏幕。`launch.sh` 脚本会创建 `/tmp/compositor.pid` 文件，以便其他脚本可以找到并控制合成器进程。
