## 简介
本文档深入解析NextUI的插件系统架构，重点阐述其动态功能扩展机制。该系统允许通过共享库（.so文件）在运行时加载新功能，实现对主应用的非侵入式扩展。文档将详细说明插件的加载、初始化、调用流程，以及插件与主应用之间的通信机制。通过分析`clock`、`gametime`和`network`插件的实例，展示如何注册UI菜单项、绑定事件回调和实现独立运行循环。文档还涵盖了插件开发的标准步骤、内存管理、线程安全和错误处理的最佳实践。特别地，文档新增了对插件间通信和动态页面调用功能的分析。

## 架构概述
NextUI的插件系统采用动态链接库（DLL）技术，实现了主应用与功能模块的解耦。系统启动时，插件管理器会扫描预定义的插件目录（`PLUGIN_PATH`），查找所有以`.so`为后缀的共享库文件。对于每个找到的库，系统使用`dlopen`加载，并通过`dlsym`查找名为`GetPlugin`的符号。该符号指向一个返回`NextUI_Plugin`结构体指针的函数。成功获取该结构体后，系统会将其信息存储在链表中，完成插件的注册。

```

participant 插件管理器 as 插件管理器
participant 插件库 as 插件库(.so)
主应用->>插件管理器 : PLUGINS_init()
插件管理器->>插件管理器 : 打开PLUGIN_PATH目录
loop 遍历目录
插件管理器->>插件管理器 : 检查文件是否为.so
插件管理器->>插件库 : dlopen(加载共享库)
插件库-->>插件管理器 : 返回句柄
插件管理器->>插件库 : dlsym(句柄, "GetPlugin")
插件库-->>插件管理器 : 返回函数指针
插件管理器->>插件库 : 调用GetPlugin()
插件库-->>插件管理器 : 返回NextUI_Plugin*
插件管理器->>插件管理器 : 验证插件信息
插件管理器->>插件管理器 : 将插件信息加入链表
插件管理器->>插件库 : dlclose(关闭库)
end
插件管理器-->>主应用 : 初始化完成
```

## 详细组件分析
### 插件接口与生命周期
插件系统的核心是`NextUI_Plugin`结构体，它定义了插件与主应用交互的契约。该结构体包含插件的名称、显示路径和三个关键的生命周期函数：`init`、`run`和`quit`。

```c
// plugin.h
typedef struct {
    const char* name;
    const char* display_path; // 新增：插件开发者在此定义路径
    int (*init)(void* screen);
    int (*run)(void);
    void (*quit)(void);
    // 功能1: 注册动作列表
    PluginAction* actions;
    int action_count;

    // 功能2: 注册页面打开函数
    // page_name: 要打开的页面标识符, e.g., "terminal_view"
    // args: 传递给页面的参数
    // 返回值: 0 表示成功, 非0表示失败
    int (*open_page)(const char* page_name, PluginArg* args);

} NextUI_Plugin;
```

- **name**: 插件的内部标识符和显示名称。
- **display_path**: 新增字段，用于定义插件在UI菜单中的显示路径，例如 `SDCARD_PATH "/Tools/Settings"`。
- **init**: 在插件首次被调用时执行，用于初始化插件的UI和状态。它接收一个指向主屏幕`SDL_Surface`的指针。
- **run**: 插件的主循环，负责处理用户输入、更新UI和执行业务逻辑。
- **quit**: 在插件退出时调用，用于释放资源和清理状态。
- **actions**: 新增字段，指向一个`PluginAction`数组，允许插件注册可被外部调用的动作。
- **action_count**: `actions`数组的长度。
- **open_page**: 新增函数指针，允许插件提供打开特定内部页面的功能，支持更复杂的导航。

### 插件加载与初始化流程
插件加载流程始于`PLUGINS_init`函数。该函数首先打开`PLUGIN_PATH`（定义为`SYSTEM_PATH "/plugins"`）目录。然后，它遍历目录中的所有文件，使用`suffixMatch(".so", dp->d_name)`筛选出共享库文件。对于每个`.so`文件，系统执行以下步骤：
1.  **加载库**: 使用`dlopen(full_path, RTLD_LAZY)`加载共享库。
2.  **解析符号**: 使用`dlsym(handle, GET_PLUGIN_SYMBOL)`查找`GetPlugin`符号。`GET_PLUGIN_SYMBOL`宏定义为字符串`"GetPlugin"`。
3.  **获取插件信息**: 调用`GetPlugin`函数，获取指向`NextUI_Plugin`结构体的指针。
4.  **验证与注册**: 检查返回的结构体是否有效（非空且名称存在），然后将其路径和名称复制到新分配的`PluginEntry`节点中，并插入到全局链表`plugin_list_head`的头部。**新增**：如果插件提供了`display_path`，也会将其复制到`PluginEntry`中。
5.  **关闭库**: 调用`dlclose(handle)`。**注意**：这里仅关闭了库句柄，但`GetPlugin`返回的函数指针和数据仍然有效，因为它们已被复制到主应用的内存空间。

### 插件间通信与动态调用
最新的代码变更引入了两个强大的API，允许主应用或其他插件动态地与已加载的插件进行交互。

#### 动作调用 (PLUGIN_invokeAction)
`PLUGIN_invokeAction`函数允许通过插件名称和动作名称来触发插件内部注册的特定功能。

```c
// api.h
int PLUGIN_invokeAction(const char* plugin_name, const char* action_name, PluginArg* args);
```

**执行流程**:
1.  **查找插件**: 通过`find_plugin_entry(plugin_name)`在全局链表中查找目标插件。
2.  **加载插件**: 调用`PLUGIN_load(entry->path)`重新加载共享库以获取最新的`NextUI_Plugin`实例。
3.  **查找动作**: 遍历插件的`actions`数组，查找与`action_name`匹配的`PluginAction`。
4.  **执行动作**: 如果找到匹配的动作且其`execute`函数指针有效，则调用该函数并传递`args`参数。

```c
// plugin.c
int PLUGIN_invokeAction(const char* plugin_name, const char* action_name, PluginArg* args) {
    LOG_note(LOG_REALTIME, "Attempting to invoke action '%s' from plugin '%s'\n", action_name, plugin_name);
    
    PluginEntry* entry = find_plugin_entry(plugin_name);
    if (!entry) {
        LOG_error("Plugin '%s' not found.\n", plugin_name);
        return -1; // 插件未找到
    }

    NextUI_Plugin* plugin = PLUGIN_load(entry->path);
    if (!plugin) {
        LOG_error("Failed to load plugin from '%s'.\n", entry->path);
        return -2; // 插件加载失败
    }

    if (!plugin->actions || plugin->action_count == 0) {
        LOG_warn("Plugin '%s' does not register any actions.\n", plugin_name);
        return -3; // 插件无动作
    }

    for (int i = 0; i < plugin->action_count; ++i) {
        if (strcmp(plugin->actions[i].name, action_name) == 0) {
            if (plugin->actions[i].execute) {
                LOG_note(LOG_REALTIME, "Executing action '%s'...\n", action_name);
                return plugin->actions[i].execute(args);
            }
        }
    }

    LOG_warn("Action '%s' not found in plugin '%s'.\n", action_name, plugin_name);
    return -4; // 动作未找到
}
```

**参数传递 (PluginArg)**:
`PluginArg`是一个链表结构，用于传递键值对参数。
```c
typedef struct PluginArg {
    char* key;
    char* value;
    struct PluginArg* next;
} PluginArg;
```
系统提供了`PLUGIN_createArg`和`PLUGIN_freeArgs`辅助函数来创建和销毁参数链表。

#### 页面打开 (PLUGIN_openPage)
`PLUGIN_openPage`函数允许直接打开插件的某个特定内部页面，实现更深层次的集成。

```c
// api.h
int PLUGIN_openPage(const char* plugin_name, const char* page_name, PluginArg* args);
```

**执行流程**:
1.  **查找插件**: 通过`find_plugin_entry(plugin_name)`在全局链表中查找目标插件。
2.  **加载插件**: 调用`PLUGIN_load(entry->path)`获取`NextUI_Plugin`实例。
3.  **调用页面函数**: 检查插件是否实现了`open_page`函数指针。如果实现，则直接调用该函数，并传入`page_name`和`args`。

```c
// plugin.c
int PLUGIN_openPage(const char* plugin_name, const char* page_name, PluginArg* args) {
    LOG_note(LOG_REALTIME, "Attempting to open page '%s' from plugin '%s'\n", page_name, plugin_name);

    PluginEntry* entry = find_plugin_entry(plugin_name);
    if (!entry) {
        LOG_error("Plugin '%s' not found.\n", plugin_name);
        return -1;
    }
    
    NextUI_Plugin* plugin = PLUGIN_load(entry->path);
    if (!plugin) {
        LOG_error("Failed to load plugin from '%s'.\n", entry->path);
        return -2;
    }

    if (!plugin->open_page) {
        LOG_warn("Plugin '%s' does not support opening specific pages.\n", plugin_name);
        return -3;
    }

    // 调用页面打开函数，它应该处理初始化并进入自己的主循环
    return plugin->open_page(page_name, args);
}
```

### Clock插件实例分析
`clock`插件是理解插件系统功能的绝佳范例。其核心是一个名为`clock_plugin`的`NextUI_Plugin`结构体实例。

```c
// clock.c
static NextUI_Plugin clock_plugin = {
    .name = "Clock",
    .display_path = SDCARD_PATH "/Tools/Settings", // 明确指定在“工具-设置”菜单下
    .init = plugin_init,
    .run = plugin_run,
    .quit = plugin_quit,
};
```

#### UI初始化 (plugin_init)
`plugin_init`函数使用`SysUI`库来设置插件的用户界面。它调用`SysUI_Init`进行初始化，`SysUI_SetTitle`设置标题为“Date and time”，并使用`SysUI_SetBottomHints`配置底部按钮提示（SELECT, 24H, A, SET, B, BACK）。

```c
// clock.c
static int plugin_init(void* main_screen) {
    screen = (SDL_Surface*)main_screen;
    quit_plugin = 0;
    
    SysUI_Init(screen, &font);
    SysUI_SetTitle("Date and time");
    SysUI_SetBottomHints("SELECT", "24H", "A", "SET", "B", "BACK");
    SysUI_SetFullscreen(false);

    return 0;
}
```

#### 主循环与事件处理 (plugin_run)
`plugin_run`函数是插件的核心，它包含一个主循环，持续处理用户输入和渲染UI。
- **输入处理**: 使用`PAD_poll()`获取输入状态，并通过`PAD_justRepeated`、`PAD_justPressed`等宏检测按钮的重复、按下和释放事件。例如，上下键用于增减时间值，左右键用于切换光标位置，A键用于保存并退出，B键用于直接退出。
- **UI渲染**: 在`dirty`标志为真时，重新渲染整个UI。它使用预渲染的数字和符号位图（`digits`）来高效地绘制时间。`SysUI_Render()`负责绘制顶部和底部的系统UI栏。
- **网络时间同步**: 如果设备在线（`PLAT_isOnline()`），插件会调用`sntp`命令行工具同步网络时间。

#### 系统交互 (plugin_quit)
`plugin_quit`函数调用`SysUI_Quit()`来清理`SysUI`库的资源。

#### 时间设置 (PLAT_setDateTime)
当用户修改时间并点击“SET”按钮后，插件会调用`PLAT_setDateTime`函数将新时间写入系统。该函数通过执行`system("date -s '...'; hwclock --utc -w")`命令来实现。

```c
// api.c
FALLBACK_IMPLEMENTATION int PLAT_setDateTime(int y, int m, int d, int h, i, s) {
    char cmd[512];
    sprintf(cmd, "date -s '%d-%d-%d %d:%d:%d'; hwclock --utc -w", y,m,d,h,i,s);
    system(cmd);
    return 0;
}
```
