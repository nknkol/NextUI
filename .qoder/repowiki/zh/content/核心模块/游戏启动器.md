## 简介
本文档深入剖析了游戏启动器（launcher）模块的工作原理。该启动器是整个模拟器系统的核心，负责解析.pak扩展包、读取配置文件、执行启动脚本，并管理从用户界面到模拟器核心的完整启动流程。文档将详细分析其代码结构、状态机设计、环境变量传递机制、UI反馈以及异常处理策略，并提供创建自定义.pak包的完整指南。本文档基于`9f8ba6b8`提交的初始代码进行分析。

### .pak包工作机制分析
.pak包是模拟器核心的封装单元，其工作机制由`launch.sh`脚本和`default.cfg`配置文件共同定义。

#### A2600.pak示例分析
**default.cfg**文件定义了输入映射：
```
bind Up = UP
bind Down = DOWN
bind Left = LEFT
bind Right = RIGHT
...
```
此文件为模拟器核心提供了默认的按键配置。

**launch.sh**脚本是启动的核心：
```bash
#!/bin/sh
EMU_EXE=stella2014
CORES_PATH=$(dirname "$0")
EMU_TAG=$(basename "$(dirname "$0")" .pak)
ROM="$1"
mkdir -p "$BIOS_PATH/$EMU_TAG"
mkdir -p "$SAVES_PATH/$EMU_TAG"
mkdir -p "$CHEATS_PATH/$EMU_TAG"
HOME="$USERDATA_PATH"
cd "$HOME"
minarch.elf "$CORES_PATH/${EMU_EXE}_libretro.so" "$ROM" > "$LOGS_PATH/$EMU_TAG.txt" 2>&1
```
该脚本的关键步骤：
1.  **设置环境**：定义`EMU_EXE`（核心可执行文件名）和`CORES_PATH`（当前.pak包路径）。
2.  **创建目录**：为BIOS、存档和金手指文件创建专属目录。
3.  **切换工作目录**：将工作目录切换到用户数据目录`$HOME`。
4.  **执行核心**：调用`minarch.elf`加载器，传入核心动态库路径和ROM路径，并将输出重定向到日志文件。

#### 创建自定义.pak包完整指南
根据`PAKS.md`文档，创建自定义.pak包需遵循以下规则：
1.  **包类型**：
    *   **重用核心**：使用系统内置的libretro核心，自定义配置。例如`GG.pak`。
    *   **自带核心**：捆绑自己的libretro核心，以支持新系统。例如`MGBA.pak`。
    *   **独立模拟器**：启动独立的非libretro模拟器，但会失去NextUI的集成功能（如快速存档、从菜单恢复）。
2.  **存放位置**：将.pak包放置在SD卡根目录的`Emus`（模拟器）或`Tools`（工具）文件夹内，**切勿**放入`.system`隐藏文件夹。
3.  **包结构**：一个.pak包本质上是一个以`.pak`为扩展名的文件夹，必须包含一个名为`launch.sh`的启动脚本。
4.  **平台特定性**：在`Emus`和`Tools`文件夹内，需要根据目标设备创建相应的平台文件夹（如`rgb30`, `tg5040`）。

### 自动恢复机制分析
启动器提供了一种自动恢复上次游戏会话的机制。

#### 机制流程
1.  **触发**：`nextui.c`在启动时调用`autoResume()`函数。
2.  **检查**：函数首先检查`AUTO_RESUME_PATH`（即`SHARED_USERDATA_PATH/.minui/auto_resume.txt`）文件是否存在。
3.  **验证**：如果文件存在，则读取其中的ROM路径，并验证该ROM文件和对应的模拟器核心文件是否都存在。
4.  **执行**：所有检查通过后，函数会：
    *   调用`system()`执行`gametimectl.elf start 'rom_path'`来记录游戏时间。
    *   调用`queueNext()`将启动命令写入`/tmp/next`文件，并设置`quit=1`以退出主循环。
    *   启动命令会使用`RESUME_SLOT_PATH`（`/tmp/resume_slot.txt`）设置为`AUTO_RESUME_SLOT`（值为9），指示核心从自动恢复槽加载状态。

## 性能考量
启动器的性能主要体现在UI响应速度和启动延迟上。代码中使用了`SDL_Delay(500)`来短暂显示加载动画，确保用户感知到系统正在工作。`Array`数据结构的实现（如`Array_push`, `Array_pop`）应关注其时间复杂度，避免在大型列表操作时产生卡顿。异步操作（如图片加载）通过线程池`initImageLoaderPool`处理，以保持主UI线程的流畅。

## 故障排除指南
1.  **游戏无法启动**：
    *   检查`.pak`包内的`launch.sh`脚本是否有执行权限。
    *   确认`CORES_PATH`和`ROM`路径是否正确传递。
    *   查看`$LOGS_PATH/$EMU_TAG.txt`日志文件以获取错误信息。
2.  **无法恢复游戏**：
    *   检查`$SHARED_USERDATA_PATH/.minui/<EMU>/<romname>.txt`存档文件是否存在。
    *   确保`can_resume`全局变量在`readyResume`后为1。
3.  **UI卡顿**：
    *   检查`Array`操作是否在大型列表上执行了低效的遍历。
    *   确认图片加载线程池是否正常工作。
4.  **自动恢复失败**：
    *   检查`SHARED_USERDATA_PATH/.minui/auto_resume.txt`文件是否存在且内容正确。
    *   确认`autoResume()`函数中检查的ROM和核心文件路径是否有效。
