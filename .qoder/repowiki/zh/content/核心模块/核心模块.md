## 核心组件
NextUI的核心由四个相互协作的模块构成：`uimanager`负责UI状态和导航，`browser`负责文件系统遍历和游戏列表加载，`datastructures`提供基础数据容器，`launcher`负责与外部模拟器核心交互。这些模块通过明确定义的函数接口和共享的全局数据结构（如`recents`数组）进行通信，形成一个完整的前端应用。

## 架构概述
NextUI采用分层架构，上层为UI和业务逻辑，下层为数据结构和平台接口。`uimanager`作为控制中心，协调`browser`获取文件列表，并通过`launcher`启动游戏。`datastructures`为所有模块提供统一的数组、哈希表等容器。`launcher`通过执行shell命令与位于`.pak`文件夹中的外部模拟器核心（launch.sh脚本）交互。

### 用户界面管理器 (uimanager) 分析
`uimanager`模块是整个应用的导航中枢，负责管理UI状态栈、处理用户导航和执行各种操作。

#### 生命周期管理
`uimanager`通过`Menu_init`和`Menu_quit`函数管理应用的生命周期。`Menu_init`初始化全局状态栈（`stack`）、最近游戏列表（`recents`），并加载上次退出时的目录状态。

```c
void Menu_init(void) {
    stack = Array_new();
    recents = Array_new();
    PLUGINS_init();
    openDirectory(SDCARD_PATH, 0);
    loadLast();
    QuickMenu_init();
}
```
**代码来源**: [uimanager.c](file://workspace/apps/nextui/uimanager.c#L80-L90)

#### 导航逻辑
导航基于一个`Directory`对象栈。`openDirectory`函数根据目标路径是否为当前目录的直接子目录，决定是简单压栈还是重建整个路径栈，确保导航一致性。

### 文件浏览器 (browser) 分析
`browser`模块负责遍历文件系统，加载游戏列表，并根据目录类型提供不同的条目。

#### 文件系统遍历
`getEntries`函数是核心，它根据传入的路径调用`addEntries`来扫描目录内容，并根据文件后缀（.pak, .so）和路径前缀（COLLECTIONS_PATH）确定条目类型。

```c
void addEntries(Array* entries, char* path) {
    DIR *dh = opendir(path);
    if (dh!=NULL) {
        struct dirent *dp;
        while((dp = readdir(dh)) != NULL) {
            if (hide(dp->d_name)) continue;
            // ... 根据dp->d_name判断类型 ...
            Array_push(entries, Entry_new(full_path, type));
        }
        closedir(dh);
    }
}
```
**代码来源**: [browser.c](file://workspace/apps/nextui/browser.c#L451-L470)

### 数据结构 (datastructures) 分析
`datastructures`模块提供了一套轻量级的通用数据容器，是整个应用的基础。

#### 核心数据结构
该模块定义了`Array`（动态数组）、`Hash`（简单哈希表）和`Entry`（文件条目）等结构。`Array`通过`realloc`实现动态扩容。

```c

**代码来源**: [datastructures.h](file://workspace/apps/nextui/include/datastructures.h#L10-L15)

#### 内存管理
所有数据结构都提供了配套的`free`函数（如`Array_free`, `Entry_free`），确保内存安全。`Entry_free`会释放其`path`、`name`和`unique`字段。

```c
void Entry_free(Entry* self) {
    free(self->path);
    free(self->name);
    if (self->unique) free(self->unique);
    free(self);
}
```

### 启动器 (launcher) 分析
`launcher`模块负责与外部模拟器核心交互，处理游戏启动、状态恢复和最近游玩记录。

#### 与模拟器核心交互
`openPak`函数通过执行`.pak`目录下的`launch.sh`脚本来启动模拟器。它使用`queueNext`将shell命令写入`/tmp/next`文件，由系统读取并执行。

```c
void openPak(char* path) {
    saveLast(path);
    char cmd[256];
    sprintf(cmd, "'%s/launch.sh'", escapeSingleQuotes(path));
    queueNext(cmd);
}
```
**代码来源**: [launcher.c](file://workspace/apps/nextui/launcher.c#L171-L176)

#### 状态恢复流程
`readyResume`和`autoResume`函数检查存档文件（`.txt`）和预览图（`.bmp`）是否存在，以决定是否可以恢复游戏状态。`openRom`在启动前会设置`gametimectl`并生成启动命令。

## 性能考虑
- **内存分配**: `Array`的动态扩容策略（容量翻倍）减少了`realloc`调用次数，提高了性能。
- **文件I/O**: `hasRecents`等函数在检查文件存在性时会频繁调用`exists`，可能成为瓶颈，建议缓存结果。
- **字符串操作**: `replaceString`等函数递归操作字符串，对于长路径可能效率不高。

## 故障排除指南
- **游戏无法启动**: 检查`.pak`目录下的`launch.sh`脚本是否存在且有执行权限。
- **列表不显示**: 确认`ROMS_PATH`和`SDCARD_PATH`等路径配置正确，目标目录存在且非空。
- **UI卡顿**: 检查`Directory_index`函数，大量文件时排序和索引可能耗时，可考虑异步处理。
