## 分层架构设计

NextUI系统采用清晰的分层架构设计，各层职责分明，通过定义良好的接口进行通信。

### 应用层 (nextui)
作为系统的用户界面核心，`nextui` 应用层负责UI渲染、用户输入处理和导航逻辑。其主要职责包括：
- **UI渲染**：使用SDL2进行图形绘制，管理多层渲染（背景、缩略图、滚动文本等）
- **输入处理**：通过`PAD_poll()`轮询手柄输入，处理按钮事件
- **状态管理**：维护当前选中项、目录堆栈、最近游戏列表等状态
- **模块协调**：调用服务层接口获取电池、WiFi状态，控制音量、亮度等系统功能

### 服务层 (batmon, wifimanager)
服务层提供后台系统服务，以守护进程形式运行，与应用层通过IPC或共享文件进行通信。

#### 电池监控服务 (batmon)
- **功能**：监控电池电量和充电状态，记录使用日志
- **实现**：`batmon.c` 通过`PLAT_getBatteryStatus()`定期查询电池状态，使用SQLite数据库记录使用时长
- **交互**：应用层通过`PWR_getBattery()`和`PWR_isCharging()`获取实时状态

#### WiFi管理服务 (wifimanager)
- **功能**：管理WiFi连接、扫描网络、处理认证
- **实现**：`wifi_daemon.c` 作为守护进程，通过`wpa_supplicant`接口管理WiFi状态机
- **交互**：应用层通过`WIFI_scan()`、`WIFI_connect()`等API进行网络操作

### 库层 (libcommon)
`libcommon` 提供跨层共享的基础功能和抽象接口。

- **API抽象**：`api.h` 定义了统一的API接口，如`GFX_init()`、`PAD_init()`，屏蔽底层差异
- **配置管理**：`config.c` 处理系统配置文件的读写
- **插件系统**：`plugin.c` 支持动态加载`.pak`扩展包。**注意**：根据`defines.h`中的定义，插件路径已从`/plugin`更新为`/plugins`，以匹配目录重命名。
- **多语言支持**：`lang.c` 实现中英文界面切换

### 硬件抽象层
通过`platform.h`和`api.h`中的`PLAT_*`前缀函数，实现对不同硬件平台的抽象。

- **输入抽象**：将物理按键（如`BTN_POWER`）映射到逻辑按钮（`BTN_SLEEP`）
- **显示抽象**：`PLAT_initVideo()`初始化显示设备，`PLAT_setVsync()`控制垂直同步
- **电源管理**：`PLAT_setCPUSpeed()`动态调整CPU频率，`PLAT_deepSleep()`支持深度睡眠

## 事件驱动模型与主循环

``mermaid
sequenceDiagram
participant Input as 输入处理
participant Event as 事件循环
participant Render as 渲染系统
participant Service as 后台服务
loop 主循环
Input->>Event : PAD_poll()
Event->>Event : 处理按钮事件
Event->>Event : PWR_update()检查电源状态
alt UI需要更新
Event->>Render : 设置dirty标志
end
Event->>Render : GFX_startFrame()
alt dirty为真
Render->>Render : 执行完整渲染
Render->>Render : 处理动画和过渡效果
else 动画或资源加载
Render->>Render : 执行增量渲染
else 无需绘制
Render->>Render : SDL_Delay(17)节流
end
Render->>Event : GFX_sync_fixed_rate(60.0)
Event->>Service : 协调服务通信
end
```

**图示来源**  
- [nextui.c](file://workspace/apps/nextui/nextui.c#L200-L1211)

NextUI采用事件驱动的主循环模型，核心逻辑位于`nextui.c`的`main()`函数中。

### 主循环流程
1. **输入轮询**：调用`PAD_poll()`获取当前输入状态
2. **状态更新**：`PWR_update()`检查电源按钮、充电状态变化
3. **事件处理**：根据`currentScreen`状态处理不同屏幕的按钮事件
4. **渲染决策**：基于`dirty`标志决定渲染策略
5. **帧同步**：通过`GFX_sync_fixed_rate(60.0)`保持60FPS

### 渲染策略
系统采用多层渲染和条件绘制策略优化性能：

- **脏标记机制**：`dirty`变量控制是否需要重新渲染，避免不必要的绘制开销
- **分层管理**：使用`LAYER_BACKGROUND`、`LAYER_THUMBNAIL`等层分离不同内容
- **动画处理**：`GFX_animateSurface()`系列函数实现平滑的过渡动画
- **资源异步加载**：`initImageLoaderPool()`创建线程池异步加载背景和缩略图

### 启动脚本分析
`runtrimui.sh`是系统的入口脚本，负责启动前的环境准备：

1. **等待SD卡挂载**：循环检查`/proc/mounts`确保SD卡已就绪
2. **更新检查**：检测`/mnt/SDCARD/.tmp_update/updater`是否存在，优先执行系统更新
3. **启动主程序**：调用`runtrimui-original.sh`最终启动`nextui`

### 主程序初始化
`main()`函数的初始化顺序体现了关键的设计考量：

```c
int main (int argc, char *argv[]) {
    if (autoResume()) return 0; // 自动恢复游戏
    simple_mode = exists(SIMPLE_MODE_PATH);
    LOG_info("NextUI\n");
    InitSettings(); // 初始化配置
    
    // 关键初始化顺序
    screen = GFX_init(MODE_MAIN); // 1. 图形系统优先
    PAD_init(); // 2. 输入系统

    pthread_create(&cpucheckthread, NULL, PLAT_cpu_monitor, NULL); // 8. CPU监控线程
    
    GFX_setVsync(VSYNC_STRICT); // 9. 设置垂直同步
    // ... 进入主循环
}

## 模块初始化与关键设计

### 关键设计决策

#### 性能考量
- **异步资源加载**：`initImageLoaderPool()`创建独立线程加载耗时的背景和缩略图，避免阻塞主UI线程
- **分层渲染**：通过`LAYER_*`机制，只重绘变化的图层，减少GPU负载
- **帧率控制**：`GFX_sync_fixed_rate(60.0)`确保稳定的60FPS，`SDL_Delay(17)`实现基本的节流

#### 稳定性考量
- **错误处理**：`wifi_daemon.c`中对`wpa_supplicant`连接进行5次重试，提高网络稳定性
- **资源清理**：在`main()`函数末尾调用`QuitSettings()`、`GFX_quit()`等清理函数
- **信号处理**：`batmon.c`注册`SIGTERM`、`SIGINT`信号处理器，实现优雅退出

### 核心数据结构
```c
// 目录结构
Directory* top; // 当前目录
Array* stack;  // 目录堆栈，实现导航

// 列表状态
int top->selected; // 当前选中项
int top->start;    // 可见项起始索引
int top->end;      // 可见项结束索引

// 全局状态
int quit;         // 退出标志
int dirty;        // 脏标记，控制重绘
int currentScreen;// 当前屏幕状态
```

这些设计确保了NextUI在资源受限的嵌入式设备上能够提供流畅、稳定的用户体验。
