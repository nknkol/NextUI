## 项目结构

终端插件是NextUI系统中的一个功能模块，位于`workspace/plugins/terminal`目录下。该插件主要由两个文件构成：`terminal.c`和`makefile`。`terminal.c`是插件的主要实现文件，包含了所有业务逻辑、用户界面渲染和系统交互代码。`makefile`则定义了插件的编译规则和依赖项。

## 核心组件

终端插件的核心功能围绕会话管理、PTY（伪终端）会话创建和libtsm库集成展开。主要组件包括：
- **会话管理**：通过`TerminalSession`结构体管理多个终端会话，支持创建、删除和切换。
- **PTY会话**：使用`openpty()`和`fork()`系统调用创建真实的终端环境。
- **libtsm集成**：利用libtsm库处理终端的屏幕渲染和虚拟终端仿真。
- **用户界面**：提供会话列表视图和全屏终端视图，支持虚拟键盘输入。

#### PTY会话工作原理

PTY会话的创建通过`initialize_real_terminal()`函数实现，其工作流程如下：

```
sequenceDiagram
participant Plugin as 终端插件
participant PTY as openpty()
participant Fork as fork()
participant Child as 子进程
participant Parent as 父进程
participant Libtsm as libtsm
Plugin->>PTY : 调用openpty()创建PTY对
PTY-->>Plugin : 返回ptm_fd和pts_fd
Plugin->>Fork : 调用fork()创建子进程
Fork->>Child : 子进程执行
Child->>Child : setsid()创建新会话
Child->>Child : ioctl(TIOCSCTTY)设置控制终端
Child->>Child : dup2()重定向标准流
Child->>Child : execv("/bin/sh")启动shell
Fork->>Parent : 父进程继续执行
Parent->>Parent : close(pts_fd)关闭从设备
Parent->>Parent : fcntl(O_NONBLOCK)设置非阻塞模式
Parent->>Libtsm : tsm_screen_new()创建屏幕
Parent->>Libtsm : tsm_vte_new()创建虚拟终端
Parent->>Libtsm : tsm_screen_resize()调整屏幕大小
Parent-->>Plugin : 返回初始化成功
```

### libtsm集成方式

终端插件通过libtsm库实现终端仿真功能，主要涉及屏幕渲染和虚拟终端处理。集成方式如下：

```
flowchart TD
Start([插件初始化]) --> LoadLibtsm["加载libtsm库"]
LoadLibtsm --> CreateScreen["调用tsm_screen_new()创建屏幕"]
CreateScreen --> CreateVte["调用tsm_vte_new()创建虚拟终端"]
CreateVte --> SetCallbacks["设置vte_write_cb和draw_cb回调"]
SetCallbacks --> HandleInput["处理用户输入: write()到ptm_fd"]
HandleInput --> ReadOutput["从ptm_fd读取输出"]
ReadOutput --> ProcessOutput["调用tsm_vte_input()处理输出"]
ProcessOutput --> Render["调用tsm_screen_draw()渲染屏幕"]
Render --> End([显示终端])
```

### OSK布局与输入处理

#### OSK功能键分离
终端插件的虚拟键盘（OSK）布局已进行重设计，将功能键（如ESC、TAB、RET、BS、SPC、↑、↓、HIDE）从主键盘布局中分离出来，形成一个独立的功能键行。这提高了功能键的可访问性和可见性。

```

+static bool osk_active : 键盘可见性状态
+static int osk_x, osk_y : 当前选中键的坐标
}
```

### 终端缩放机制

终端插件引入了动态缩放功能，允许用户根据需要调整终端显示大小。缩放范围为50%到200%，步长为10%。通过SELECT+L1/R1组合键进行缩放操作。

```
flowchart TD
Start([用户按下SELECT+R1]) --> CheckScale["检查当前缩放级别"]
CheckScale --> MaxScale{是否达到MAX_SCALE?}
MaxScale -- 否 --> Increase["terminal_scale += SCALE_STEP"]
MaxScale -- 是 --> NoOp1[无操作]
Increase --> UpdateSize["调用update_terminal_size()"]
UpdateSize --> MarkDirty["标记需要重绘"]
MarkDirty --> Render["在render_terminal_view中应用缩放"]

Start2([用户按下SELECT+L1]) --> CheckScale2["检查当前缩放级别"]
CheckScale2 --> MinScale{是否达到MIN_SCALE?}
MinScale -- 否 --> Decrease["terminal_scale -= SCALE_STEP"]
MinScale -- 是 --> NoOp2[无操作]
Decrease --> UpdateSize2["调用update_terminal_size()"]
UpdateSize2 --> MarkDirty2["标记需要重绘"]
MarkDirty2 --> Render2["在render_terminal_view中应用缩放"]
```

## 故障排除指南

### 常见问题及解决方案

**问题1：无法创建终端会话**
- **可能原因**：PTY设备不可用或权限不足
- **解决方案**：检查系统PTY配置，确保`/dev/ptmx`存在且可访问

**问题2：字体加载失败**
- **可能原因**：`mono.ttf`或`font.ttf`文件缺失
- **解决方案**：确认`RES_PATH`目录下存在字体文件

**问题3：libtsm库加载失败**
- **可能原因**：libtsm未正确编译或路径错误
- **解决方案**：检查`other/libtsm`目录，重新运行构建脚本

**问题4：输入无响应**
- **可能原因**：虚拟键盘坐标错误或事件处理异常
- **解决方案**：检查`osk_x`和`osk_y`变量的边界条件

**问题5：会话意外终止**
- **可能原因**：子进程崩溃或PTY读取错误
- **解决方案**：查看日志中的`PTY read error`信息，检查子进程环境变量

**问题6：无法通过L1键切换OSK可见性**
- **可能原因**：L1键输入事件未被正确捕获或处理逻辑被破坏
- **解决方案**：检查`terminal.c`中`PAD_justPressed(BTN_L1)`的处理逻辑，确保`osk_active`变量被正确切换。

**问题7：终端显示模糊或字体大小不正确**
- **可能原因**：`TERMINAL_FONT_WIDTH/HEIGHT`宏定义与实际渲染逻辑不匹配
- **解决方案**：确认代码中字体大小的使用，当前实现使用`SCALE1(9)`作为字体大小，而非基于宏计算。

**问题8：终端缩放功能无效**
- **可能原因**：未正确按下SELECT+R1/L1组合键
- **解决方案**：确保先按住SELECT键，再按R1（放大）或L1（缩小）键。

**问题9：右侧功能面板无法切换或选择**
- **可能原因**：焦点未正确切换到面板或R1键处理逻辑异常
- **解决方案**：检查`terminal.c`中`PAD_justPressed(BTN_R1)`和`focus_on_panel`变量的处理逻辑。

**问题10：代码片段插入失败**
- **可能原因**：面板焦点未激活或`quick_snippets`数组访问越界
- **解决方案**：确保在PANEL_SNIPPETS模式下，且`panel_selected`值在有效范围内。
